# 🧬 جلسه بعد: قفسه‌بندی داده‌ها در آزمایشگاه R؛ آشنایی با ساختمان داده‌ها

در جلسه قبل به یک اصل بسیار مهم رسیدیم:

> «هر چیزی که در R وجود دارد، یک شیء است.»

اما اینجا یک سؤال مهم به وجود می‌آید:

اگر همه‌چیز در R یک شیء است، آیا همه اشیاء شبیه یکدیگرند؟

آیا R اطلاعات مربوط به سن بیماران، نام ژن‌ها، ماتریس شمارش RNA-Seq و نتیجه یک آزمون آماری را به یک شکل در حافظه نگهداری می‌کند؟

قطعاً نه!

بیایید دوباره به آزمایشگاه واقعی برگردیم. در یک آزمایشگاه، همه مواد را داخل یک ظرف نمی‌ریزیم. برای نگهداری نمونه‌های کوچک از میکروتیوب، برای کشت سلول از فلاسک، برای نگهداری محلول از بطری و برای مرتب‌کردن نمونه‌ها از رک استفاده می‌کنیم.

داده‌ها نیز در آزمایشگاه دیجیتال ما شکل‌های متفاوتی دارند و برای نگهداری هرکدام باید ظرف مناسبی انتخاب کنیم.

به شکل‌هایی که R برای سازمان‌دهی و نگهداری داده‌ها در اختیار ما قرار می‌دهد، **ساختمان داده** یا `Data Structure` می‌گوییم.

> [!NOTE]
> در این فصل، علاوه بر شناخت هر ساختمان داده، یاد می‌گیریم چگونه عناصر آن را **انتخاب**، **تغییر** و **حذف** کنیم.

## ۱. نوع داده با ساختمان داده چه تفاوتی دارد؟

قبل از ورود به بحث اصلی، باید دو مفهوم را از یکدیگر جدا کنیم:

1. **نوع داده (`Data Type`)**
2. **ساختمان داده (`Data Structure`)**

این دو مفهوم شبیه یکدیگرند، اما یکسان نیستند.

### 🧪 معادل آزمایشگاهی

فرض کنید چند میکروتیوب روی میز داریم.

محتوای داخل هر میکروتیوب می‌تواند متفاوت باشد:

* خون
* سرم
* RNA
* بافر
* آب مقطر

این محتوا، معادل **نوع داده** است.

اما خود میکروتیوب، رک، پلیت یا فلاسکی که مواد را در آن قرار می‌دهیم، معادل **ساختمان داده** است.

در R نیز مقادیر ما می‌توانند انواع مختلفی داشته باشند:

```r
25
```

یک مقدار عددی است.

```r
"TP53"
```

یک مقدار متنی است.

```r
TRUE
```

یک مقدار منطقی است.

اما این مقادیر باید داخل ظرف‌هایی مانند بردار، ماتریس، دیتا فریم یا لیست سازمان‌دهی شوند.

> نوع داده مشخص می‌کند «چه چیزی» را ذخیره کرده‌ایم؛ ساختمان داده مشخص می‌کند آن چیزها را «چگونه کنار هم» قرار داده‌ایم.

## انواع داده در R

اکنون که تفاوت «نوع داده» و «ساختمان داده» را می‌دانیم، باید با انواع داده‌ای که R می‌تواند ذخیره کند آشنا شویم.

در R، داده‌ها را می‌توان در چند گروه اصلی دسته‌بندی کرد:

```text
انواع داده در R
│
├── انواع اتمی (Atomic Types)
│   ├── Logical
│   ├── Integer
│   ├── Double / Numeric
│   ├── Complex
│   ├── Character
│   └── Raw
│
├── مقادیر ویژه (Special Values)
│   ├── NA
│   ├── NaN
│   ├── Inf
│   ├── -Inf
│   └── NULL
│
└── کلاس‌های پرکاربرد برای نمایش داده
    ├── Factor
    ├── Date
    ├── POSIXct / POSIXlt
    └── Difftime
```

> [!NOTE]
> انواع اتمی، بنیادی‌ترین انواع داده در R هستند. ساختمان‌هایی مانند بردار و ماتریس معمولاً از همین مقادیر اتمی ساخته می‌شوند.

---

### ۱. داده منطقی (`Logical`)

داده منطقی فقط می‌تواند یکی از دو مقدار زیر را داشته باشد:

```r
TRUE
FALSE
```

مثلاً وضعیت عبور نمونه‌ها از کنترل کیفیت:

```r
passed_qc <- c(TRUE, TRUE, FALSE, TRUE)
```

برای بررسی نوع داده:

```r
typeof(passed_qc)
```

خروجی:

```text
[1] "logical"
```

در R می‌توان از شکل‌های کوتاه `T` و `F` نیز استفاده کرد، اما این کار توصیه نمی‌شود:

```r
T
F
```

زیرا برخلاف `TRUE` و `FALSE`، حروف `T` و `F` می‌توانند بازنویسی شوند.

```r
T <- 25
```

بنابراین بهتر است همیشه از شکل کامل زیر استفاده کنیم:

```r
TRUE
FALSE
```

---

### ۲. عدد صحیح (`Integer`)

عدد صحیح، عددی بدون بخش اعشاری است.

برای اینکه R یک عدد را صراحتاً از نوع `integer` در نظر بگیرد، حرف `L` را بعد از آن قرار می‌دهیم:

```r
read_count <- 120L
```

بررسی نوع:

```r
typeof(read_count)
```

خروجی:

```text
[1] "integer"
```

مثال‌های دیگر:

```r
gene_count <- 200L
replicate_number <- 3L
chromosome_number <- 7L
```

> [!IMPORTANT]
> نوشتن عدد `120` بدون حرف `L` معمولاً یک مقدار `double` ایجاد می‌کند، نه `integer`.

```r
typeof(120)
```

```text
[1] "double"
```

اما:

```r
typeof(120L)
```

```text
[1] "integer"
```

---

### ۳. عدد اعشاری یا ممیز شناور (`Double`)

نوع `double` رایج‌ترین نوع عددی در R است.

اعدادی که به‌صورت معمول می‌نویسیم، حتی اگر ظاهراً اعشار نداشته باشند، اغلب از نوع `double` هستند:

```r
gene_expression <- 12.5
```

```r
typeof(gene_expression)
```

خروجی:

```text
[1] "double"
```

حتی مقدار زیر نیز معمولاً `double` است:

```r
sample_count <- 120
```

```r
typeof(sample_count)
```

خروجی:

```text
[1] "double"
```

نمونه‌هایی از داده‌های `double` در زیست‌شناسی:

```r
fold_change <- 2.35
p_value <- 0.004
gc_content <- 48.7
patient_weight <- 72.4
```

---

### تفاوت `Numeric` و `Double`

ممکن است هنگام بررسی یک شیء با دو اصطلاح روبه‌رو شوید:

```r
class(sample_count)
```

خروجی:

```text
[1] "numeric"
```

اما:

```r
typeof(sample_count)
```

خروجی:

```text
[1] "double"
```

این دو خروجی متناقض نیستند.

- `typeof()` نوع داخلی ذخیره‌سازی داده را گزارش می‌کند.
- `class()` نحوه رفتار و نمایش شیء را گزارش می‌کند.
- در بسیاری از موارد، یک مقدار از نظر داخلی `double` و از نظر کلاس `numeric` است.

تابع زیر بررسی می‌کند که یک شیء عددی است یا خیر:

```r
is.numeric(sample_count)
```

خروجی:

```text
[1] TRUE
```

نکته جالب این است که `integer` نیز در R عددی محسوب می‌شود:

```r
is.numeric(120L)
```

```text
[1] TRUE
```

---

### ۴. عدد مختلط (`Complex`)

R می‌تواند اعداد مختلط را نیز ذخیره و محاسبه کند.

عدد مختلط از دو بخش تشکیل می‌شود:

```text
بخش حقیقی + بخش موهومی
```

در R برای نمایش بخش موهومی از حرف `i` استفاده می‌کنیم:

```r
complex_number <- 3 + 2i
```

بررسی نوع:

```r
typeof(complex_number)
```

خروجی:

```text
[1] "complex"
```

مثال‌های دیگر:

```r
z1 <- 1 + 4i
z2 <- -3 + 0.5i
z3 <- 7i
```

R می‌تواند روی اعداد مختلط محاسبات ریاضی انجام دهد:

```r
z1 + z2
```

```r
z1 * z2
```

برای استخراج بخش حقیقی:

```r
Re(z1)
```

برای استخراج بخش موهومی:

```r
Im(z1)
```

برای محاسبه مزدوج مختلط:

```r
Conj(z1)
```

برای محاسبه اندازه یا قدر مطلق عدد مختلط:

```r
Mod(z1)
```

برای محاسبه زاویه:

```r
Arg(z1)
```

همچنین می‌توان با تابع `complex()` عدد مختلط ساخت:

```r
z4 <- complex(
  real = 3,
  imaginary = 2
)
```

> [!NOTE]
> اعداد مختلط در تحلیل‌های معمول RNA-Seq کمتر دیده می‌شوند، اما در محاسبات ریاضی، تبدیل فوریه، پردازش سیگنال و بعضی روش‌های محاسباتی کاربرد دارند.

---

### ۵. داده متنی (`Character`)

هر داده‌ای که داخل علامت نقل‌قول قرار بگیرد، از نوع متنی یا `character` است.

```r
gene_name <- "TP53"
```

```r
typeof(gene_name)
```

خروجی:

```text
[1] "character"
```

می‌توان از نقل‌قول دوتایی یا تکی استفاده کرد:

```r
"TP53"
'TP53'
```

نمونه‌های زیستی:

```r
gene_symbol <- "BRCA1"
sample_id <- "Tumor_01"
organism <- "Homo sapiens"
genome_build <- "GRCh38"
```

حتی اگر یک عدد را داخل نقل‌قول قرار دهیم، دیگر عدد نیست:

```r
patient_age <- "45"
```

```r
typeof(patient_age)
```

خروجی:

```text
[1] "character"
```

بنابراین دو مقدار زیر یکسان نیستند:

```r
45
"45"
```

مقدار اول عددی است و می‌توان روی آن محاسبات ریاضی انجام داد؛ مقدار دوم یک رشته متنی است.

---

### ۶. داده خام (`Raw`)

نوع `raw` برای نگهداری بایت‌های خام استفاده می‌شود.

این نوع داده در تحلیل‌های روزمره RNA-Seq کمتر به‌صورت مستقیم دیده می‌شود، اما در موارد زیر کاربرد دارد:

- خواندن داده‌های دودویی؛
- کار با فایل‌های فشرده؛
- انتقال داده؛
- رمزگذاری؛
- پردازش سطح پایین فایل‌ها.

برای ساخت داده خام می‌توان از تابع `charToRaw()` استفاده کرد:

```r
raw_data <- charToRaw("RNA")
```

نمایش خروجی:

```r
raw_data
```

خروجی‌ای شبیه این خواهد بود:

```text
[1] 52 4e 41
```

بررسی نوع:

```r
typeof(raw_data)
```

خروجی:

```text
[1] "raw"
```

برای تبدیل دوباره به متن:

```r
rawToChar(raw_data)
```

## مقادیر ویژه در R

علاوه بر انواع داده اصلی، R چند مقدار ویژه دارد که نبود داده، نتیجه تعریف‌نشده یا مقادیر بی‌نهایت را نمایش می‌دهند.

---

### ۷. مقدار گمشده (`NA`)

`NA` مخفف `Not Available` است و نشان می‌دهد یک مقدار وجود ندارد یا ثبت نشده است.

```r
patient_ages <- c(45, 62, NA, 51)
```

برای بررسی وجود مقدار گمشده:

```r
is.na(patient_ages)
```

خروجی:

```text
[1] FALSE FALSE  TRUE FALSE
```

برای شمارش مقادیر گمشده:

```r
sum(is.na(patient_ages))
```

در R، `NA` می‌تواند نوع مشخصی داشته باشد:

```r
NA
NA_integer_
NA_real_
NA_complex_
NA_character_
```

بررسی نوع آن‌ها:

```r
typeof(NA)
typeof(NA_integer_)
typeof(NA_real_)
typeof(NA_complex_)
typeof(NA_character_)
```

> [!WARNING]
> برای بررسی `NA` نباید از عملگر `==` استفاده کنیم.

روش نادرست:

```r
patient_ages == NA
```

روش صحیح:

```r
is.na(patient_ages)
```

---

### ۸. مقدار عددی تعریف‌نشده (`NaN`)

`NaN` مخفف `Not a Number` است.

این مقدار زمانی ایجاد می‌شود که نتیجه یک محاسبه عددی تعریف نشده باشد:

```r
0 / 0
```

خروجی:

```text
[1] NaN
```

مثال دیگر:

```r
Inf - Inf
```

برای بررسی:

```r
is.nan(0 / 0)
```

خروجی:

```text
[1] TRUE
```

`NaN` نوعی مقدار گمشده نیز محسوب می‌شود:

```r
is.na(NaN)
```

خروجی:

```text
[1] TRUE
```

اما هر `NA` الزاماً `NaN` نیست:

```r
is.nan(NA)
```

خروجی:

```text
[1] FALSE
```

---

### ۹. بی‌نهایت مثبت و منفی (`Inf` و `-Inf`)

R می‌تواند مقادیر بی‌نهایت مثبت و منفی را نمایش دهد.

```r
1 / 0
```

خروجی:

```text
[1] Inf
```

```r
-1 / 0
```

خروجی:

```text
[1] -Inf
```

برای بررسی متناهی‌بودن مقدار:

```r
is.finite(Inf)
```

خروجی:

```text
[1] FALSE
```

برای بررسی بی‌نهایت‌بودن:

```r
is.infinite(Inf)
```

خروجی:

```text
[1] TRUE
```

---

### ۱۰. مقدار تهی (`NULL`)

`NULL` به معنی نبودن کامل یک شیء یا جزء است.

```r
empty_object <- NULL
```

بررسی:

```r
is.null(empty_object)
```

خروجی:

```text
[1] TRUE
```

`NULL` با `NA` تفاوت دارد:

- `NA` یعنی یک مقدار وجود دارد، اما مقدار آن ناشناخته یا گمشده است.
- `NULL` یعنی هیچ مقدار یا عنصری وجود ندارد.

مثلاً:

```r
length(NA)
```

خروجی:

```text
[1] 1
```

اما:

```r
length(NULL)
```

خروجی:

```text
[1] 0
```

در لیست‌ها و دیتا فریم‌ها، نسبت‌دادن `NULL` می‌تواند یک جزء یا ستون را حذف کند:

```r
sample_metadata$Age <- NULL
```

## کلاس‌های رایج برای نمایش داده‌های خاص

موارد زیر از انواع اتمی مستقل نیستند؛ بلکه کلاس‌هایی هستند که روی داده‌های پایه ساخته می‌شوند و به R می‌گویند با مقادیر چگونه رفتار کند.

---

### ۱۱. فاکتور (`Factor`)

فاکتور برای نمایش داده‌های دسته‌ای استفاده می‌شود:

```r
condition <- factor(
  c("Tumor", "Normal", "Tumor")
)
```

بررسی نوع داخلی:

```r
typeof(condition)
```

خروجی:

```text
[1] "integer"
```

بررسی کلاس:

```r
class(condition)
```

خروجی:

```text
[1] "factor"
```

یعنی فاکتور از نظر داخلی بر پایه اعداد صحیح ساخته شده است، اما کلاس `factor` رفتار دسته‌ای به آن می‌دهد.

فاکتور در بخش جداگانه این فصل با جزئیات بیشتر بررسی خواهد شد.

---

### ۱۲. تاریخ (`Date`)

برای ذخیره تاریخ از کلاس `Date` استفاده می‌کنیم:

```r
experiment_date <- as.Date("2026-07-27")
```

بررسی کلاس:

```r
class(experiment_date)
```

خروجی:

```text
[1] "Date"
```

بررسی نوع داخلی:

```r
typeof(experiment_date)
```

خروجی:

```text
[1] "double"
```

در پشت صحنه، R تاریخ را به‌صورت تعداد روزهای سپری‌شده از یک مبدأ زمانی ذخیره می‌کند.

---

### ۱۳. تاریخ و زمان (`POSIXct` و `POSIXlt`)

برای ذخیره هم‌زمان تاریخ و ساعت می‌توان از کلاس‌های `POSIXct` و `POSIXlt` استفاده کرد.

```r
sequencing_time <- as.POSIXct(
  "2026-07-27 14:30:00"
)
```

```r
class(sequencing_time)
```

خروجی معمولاً:

```text
[1] "POSIXct" "POSIXt"
```

`POSIXct` زمان را به شکل عددی و فشرده ذخیره می‌کند و برای بیشتر تحلیل‌ها مناسب است.

`POSIXlt` زمان را به اجزایی مانند سال، ماه، روز، ساعت و دقیقه تفکیک می‌کند:

```r
sequencing_time_lt <- as.POSIXlt(
  sequencing_time
)
```

# بخش اول: بردار؛ نخستین رک نمونه‌های ما

## ۲. یک مقدار کافی نیست!

فرض کنید مقدار بیان ژن `TP53` را در یک نمونه اندازه‌گیری کرده‌ایم:

```r
tp53_count <- 120
```

در اینجا یک شیء ساخته‌ایم که فقط یک مقدار را نگهداری می‌کند.

اما در پروژه واقعی RNA-Seq معمولاً یک نمونه نداریم. فرض کنید مقدار بیان همین ژن را در چهار نمونه اندازه‌گیری کرده‌ایم:

* نمونه اول: 120
* نمونه دوم: 85
* نمونه سوم: 210
* نمونه چهارم: 97

آیا باید برای هر نمونه یک متغیر جداگانه بسازیم؟

```r
sample_1 <- 120
sample_2 <- 85
sample_3 <- 210
sample_4 <- 97
```

از نظر فنی می‌توانیم این کار را انجام دهیم، اما با این روش خیلی زود آزمایشگاه دیجیتال ما شلوغ و غیرقابل‌کنترل می‌شود.

اگر 100 بیمار داشته باشیم چه؟

اگر 20,000 ژن داشته باشیم چه؟

اینجاست که اولین ساختمان داده R وارد داستان می‌شود.

## ۳. بردار (`Vector`) چیست؟

بردار ساده‌ترین و بنیادی‌ترین ساختمان داده در R است. بردار مجموعه‌ای یک‌بعدی از چند مقدار است که همگی باید از **یک نوع داده** باشند.

برای ساختن بردار معمولاً از تابع `c()` استفاده می‌کنیم.

حرف `c` از واژه `Combine` به معنی «ترکیب‌کردن» آمده است.

```r
tp53_counts <- c(120, 85, 210, 97)
```

اکنون به‌جای چهار شیء جداگانه، یک شیء به نام `tp53_counts` داریم که چهار مقدار را در خود نگهداری می‌کند.

بیایید محتوای آن را ببینیم:

```r
tp53_counts
```

خروجی:

```text
[1] 120  85  210  97
```

### بردار چه شکلی دارد؟

بردار فقط یک بُعد دارد؛ یعنی عناصر آن پشت سر یکدیگر قرار می‌گیرند:

```text
120   85   210   97
```

می‌توانیم آن را شبیه یک رک خطی از میکروتیوب‌ها تصور کنیم:

```text
[120] [85] [210] [97]
```

هر خانه یک مقدار دارد، اما همه خانه‌ها متعلق به یک مجموعه‌اند.

```r
sample_ids <- c(
```

```r
is_tumor <- c(TRUE, TRUE, FALSE, FALSE)
```

```r
tp53_counts
```

## ۵. قانون طلایی بردارها: همه اعضا باید هم‌نوع باشند

بردار یک ساختمان داده **همگن** یا `Homogeneous` است.

یعنی همه عناصر آن باید یک نوع داشته باشند.

بردار زیر فقط شامل اعداد است:

```r
counts <- c(120, 85, 210, 97)
```

بردار زیر فقط شامل متن است:

```r
genes <- c("TP53", "BRCA1", "EGFR")
```

بردار زیر فقط شامل مقادیر منطقی است:

```r
passed_qc <- c(TRUE, TRUE, FALSE)
```

اما اگر عدد و متن را با هم مخلوط کنیم چه اتفاقی می‌افتد؟

```r
mixed_vector <- c(120, 85, "Not_detected", 97)
```

ممکن است انتظار داشته باشیم R عددها را عدد و عبارت `Not_detected` را متن نگه دارد؛ اما بردار اجازه چنین کاری را نمی‌دهد.

بنابراین R تمام عناصر را به یک نوع مشترک تبدیل می‌کند:

```r
mixed_vector
```

خروجی:

```text
[1] "120"          "85"           "Not_detected" "97"
```

حتی عددهای `120` و `85` نیز اکنون متن شده‌اند.

به این تبدیل خودکار، **وادارسازی نوع** یا `Type Coercion` می‌گوییم.

### چرا R این کار را انجام داد؟

چون متن نمی‌تواند به‌سادگی به عدد تبدیل شود، اما عدد را می‌توان به شکل متن نمایش داد. بنابراین R نوعی را انتخاب می‌کند که بتواند همه مقادیر را در خود جای دهد.

> در یک بردار، وجود حتی یک عنصر متنی می‌تواند کل بردار عددی را به بردار متنی تبدیل کند.

این موضوع در تحلیل داده‌های زیستی بسیار مهم است. گاهی وجود عباراتی مانند `"NA"`، `"unknown"` یا `"not detected"` در یک ستون عددی باعث می‌شود کل ستون به متن تبدیل شود و محاسبات آماری روی آن انجام نشود.

## ۷. نام‌گذاری عناصر بردار

اکنون می‌دانیم مقادیر `120`، `85`، `210` و `97` متعلق به چهار نمونه هستند؛ اما از روی خود بردار نمی‌توانیم بفهمیم هر مقدار مربوط به کدام نمونه است.

می‌توانیم برای عناصر بردار نام تعیین کنیم:

```r
names(tp53_counts) <- c(
  "Tumor_1",
  "Tumor_2",
  "Normal_1",
  "Normal_2"
)
```

اکنون بردار را نمایش می‌دهیم:

```r
tp53_counts
```

خروجی:

```text
 Tumor_1  Tumor_2 Normal_1 Normal_2
      120       85      210       97
```

حالا هر مقدار یک هویت زیستی پیدا کرده است.

می‌توانیم مقدار مربوط به یک نمونه مشخص را با نام آن استخراج کنیم:

```r
tp53_counts["Tumor_1"]
```

یا با موقعیت عددی:

```r
tp53_counts[1]
```

علامت براکت `[]` در R برای **انتخاب یا استخراج بخشی از یک شیء** استفاده می‌شود. در بخش‌های آینده، این موضوع را با جزئیات بیشتری بررسی خواهیم کرد.

### 🔍 انتخاب، ✏️ تغییر و 🗑️ حذف عناصر بردار

#### انتخاب عناصر

انتخاب عنصر اول:

```r
tp53_counts[1]
```

انتخاب چند عنصر:

```r
tp53_counts[c(1, 3)]
```

انتخاب یک بازه:

```r
tp53_counts[2:4]
```

انتخاب براساس نام:

```r
tp53_counts[c("Tumor_1", "Normal_1")]
```

انتخاب براساس شرط:

```r
tp53_counts[tp53_counts > 100]
```

#### تغییر عناصر

تغییر عنصر دوم:

```r
tp53_counts[2] <- 95
```

تغییر براساس نام:

```r
tp53_counts["Tumor_2"] <- 95
```

تغییر هم‌زمان چند عنصر:

```r
tp53_counts[c("Tumor_1", "Tumor_2")] <- c(125, 100)
```

تغییر براساس شرط:

```r
tp53_counts[tp53_counts < 100] <- 0
```

#### حذف عناصر

در R معمولاً برای حذف یک عنصر، تمام عناصر **به‌جز آن عنصر** را انتخاب می‌کنیم.

حذف اولین عنصر:

```r
tp53_counts <- tp53_counts[-1]
```

حذف آخرین عنصر:

```r
tp53_counts <- tp53_counts[-length(tp53_counts)]
```

حذف یک عنصر از وسط:

```r
tp53_counts <- tp53_counts[-2]
```

حذف چند عنصر:

```r
tp53_counts <- tp53_counts[-c(1, 3)]
```

حذف براساس نام:

```r
tp53_counts <- tp53_counts[
  names(tp53_counts) != "Tumor_2"
]
```

حذف براساس شرط:

```r
tp53_counts <- tp53_counts[
  tp53_counts >= 100
]
```

حذف مقادیر گمشده:

```r
tp53_counts <- tp53_counts[
  !is.na(tp53_counts)
]
```

> [!IMPORTANT]
> نوشتن `tp53_counts[-2]` فقط نتیجه را نمایش می‌دهد. برای ذخیره تغییر باید نتیجه را دوباره در همان شیء قرار دهیم:
>
> ```r
> tp53_counts <- tp53_counts[-2]
> ```

# بخش دوم: ماتریس؛ وقتی یک ژن دیگر کافی نیست

## ۸. از یک ژن به هزاران ژن

بردار برای نگهداری میزان بیان یک ژن در چند نمونه مناسب بود:

```r
tp53_counts <- c(120, 85, 210, 97)
```

اما RNA-Seq فقط بیان یک ژن را اندازه‌گیری نمی‌کند.

فرض کنید میزان بیان سه ژن را در چهار نمونه داریم:

| Gene  | Tumor_1 | Tumor_2 | Normal_1 | Normal_2 |
| ----- | ------: | ------: | -------: | -------: |
| TP53  |     120 |      85 |      210 |       97 |
| BRCA1 |      65 |      70 |       42 |       38 |
| EGFR  |     340 |     290 |      110 |       95 |

آیا برای هر ژن یک بردار جداگانه بسازیم؟

```r
tp53_counts <- c(120, 85, 210, 97)
brca1_counts <- c(65, 70, 42, 38)
egfr_counts <- c(340, 290, 110, 95)
```

برای سه ژن هنوز قابل‌تحمل است؛ اما برای 20,000 ژن، ساختن 20,000 بردار جداگانه منطقی نیست.

ما به ساختمانی نیاز داریم که چند بردار مرتبط را به شکل سطر و ستون کنار یکدیگر قرار دهد.

## ۹. ماتریس (`Matrix`) چیست؟

ماتریس یک ساختمان داده دوبعدی و همگن است.

دوبعدی یعنی دارای:

* سطر (`Row`)
* ستون (`Column`)

است.

در ماتریس بیان ژن معمولاً:

* هر سطر نماینده یک ژن است؛
* هر ستون نماینده یک نمونه است؛
* هر خانه مقدار بیان یک ژن در یک نمونه را نگهداری می‌کند.

### 🧪 معادل آزمایشگاهی

اگر بردار را یک ردیف میکروتیوب تصور کنیم، ماتریس شبیه یک پلیت آزمایشگاهی است.

در یک پلیت، نمونه‌ها فقط در یک خط قرار ندارند؛ بلکه در چند سطر و چند ستون سازمان‌دهی شده‌اند.

## ۱۰. ساخت نخستین ماتریس بیان ژن

ابتدا تمام اعداد را در یک بردار قرار می‌دهیم:

```r
expression_values <- c(
  120, 65, 340,
  85, 70, 290,
  210, 42, 110,
  97, 38, 95
)
```

سپس با تابع `matrix()` آن را به یک ماتریس تبدیل می‌کنیم:

```r
count_matrix <- matrix(
  expression_values,
  nrow = 3,
  ncol = 4
)
```

اکنون ماتریس را نمایش می‌دهیم:

```r
count_matrix
```

### نکته بسیار مهم: R ماتریس را چگونه پر می‌کند؟

R به‌صورت پیش‌فرض مقادیر را **ستون‌به‌ستون** داخل ماتریس قرار می‌دهد، نه سطر‌به‌سطر.

یعنی ابتدا ستون اول، سپس ستون دوم و به همین ترتیب پر می‌شود.

به همین دلیل، ترتیب اعداد در بردار اولیه اهمیت دارد.

اگر بخواهیم ماتریس سطر‌به‌سطر پر شود، باید از آرگومان زیر استفاده کنیم:

```r
byrow = TRUE
```

مثلاً:

```r
count_matrix <- matrix(
  c(
    120, 85, 210, 97,
    65, 70, 42, 38,
    340, 290, 110, 95
  ),
  nrow = 3,
  byrow = TRUE
)
```

## ۱۱. دادن هویت زیستی به سطرها و ستون‌ها

ماتریس فعلی فقط مجموعه‌ای از اعداد است. هنوز معلوم نیست هر سطر متعلق به کدام ژن و هر ستون متعلق به کدام نمونه است.

نام سطرها را مشخص می‌کنیم:

```r
rownames(count_matrix) <- c(
  "TP53",
  "BRCA1",
  "EGFR"
)
```

نام ستون‌ها را نیز مشخص می‌کنیم:

```r
colnames(count_matrix) <- c(
  "Tumor_1",
  "Tumor_2",
  "Normal_1",
  "Normal_2"
)
```

اکنون:

```r
count_matrix
```

خروجی:

```text
      Tumor_1 Tumor_2 Normal_1 Normal_2
TP53      120      85      210       97
BRCA1      65      70       42       38
EGFR      340     290      110       95
```

این ساختار، نسخه بسیار کوچک‌شده‌ای از همان چیزی است که در تحلیل RNA-Seq با آن سروکار خواهیم داشت:

> یک ماتریس شمارش (`Count Matrix`) که سطرهای آن ژن‌ها و ستون‌های آن نمونه‌ها هستند.

```r
ncol(count_matrix)
```

برای مشاهده نام ابعاد:

```r
dimnames(count_matrix)
```

برای بررسی ساختار کلی:

```r
str(count_matrix)
```

---

## ۱۳. انتخاب یک ژن یا یک نمونه از ماتریس

در یک ماتریس، داخل براکت دو جایگاه داریم:

```r

```

یعنی:

```text
ماتریس[سطر، ستون]
```

```r
count_matrix["TP53", "Tumor_1"]
```

برای استخراج تمام ژن‌های نمونه `Tumor_1`:

```r
count_matrix[, "Tumor_1"]
```

این بار جای سطر را خالی گذاشته‌ایم؛ یعنی همه سطرها را می‌خواهیم.

### 🔍 انتخاب، ✏️ تغییر و 🗑️ حذف در ماتریس

قاعده کلی همچنان این است:


#### انتخاب

```r
count_matrix["TP53", "Tumor_1"] <- 130
```

---

## ۱۴. قانون ماتریس: همه خانه‌ها باید هم‌نوع باشند

ماتریس نیز مانند بردار یک ساختمان داده همگن است.

اگر یک مقدار متنی را وارد ماتریس عددی کنیم، تمام ماتریس می‌تواند به متن تبدیل شود.

```r
bad_matrix <- matrix(
  c(120, 85, 210, "Not_detected"),
  nrow = 2
)
```

در چنین شرایطی دیگر عملیات عددی معمول روی ماتریس به‌درستی انجام نمی‌شود.

این همان دلیلی است که اطلاعاتی مانند:

* سن بیمار
* جنسیت
* گروه درمان
* وضعیت بیماری

را معمولاً داخل ماتریس شمارش ژن‌ها قرار نمی‌دهیم.

ماتریس شمارش باید عددی باقی بماند. اطلاعات توصیفی نمونه‌ها را در ظرف دیگری به نام **دیتا فریم** ذخیره خواهیم کرد.

اما قبل از آن، یک سؤال دیگر داریم.

---

# بخش سوم: آرایه؛ وقتی سطر و ستون کافی نیست

## ۱۵. اگر داده ما سه بُعد داشته باشد چه؟

ماتریس برای سازمان‌دهی دو بُعد عالی بود:

```text
ژن × نمونه
```

اما فرض کنید آزمایش RNA-Seq را در چند زمان مختلف تکرار کرده‌ایم:

```text
ژن × نمونه × زمان
```

مثلاً بیان سه ژن را در دو بیمار و در سه زمان اندازه‌گیری کرده‌ایم:

* قبل از درمان
* 12 ساعت بعد
* 24 ساعت بعد

در این حالت یک جدول دوبعدی دیگر کافی نیست.

ما به ساختمانی با سه بُعد نیاز داریم.

---

## ۱۶. آرایه (`Array`) چیست؟

آرایه شکل توسعه‌یافته ماتریس است.

* بردار: یک بُعد
* ماتریس: دو بُعد
* آرایه: دو یا چند بُعد

آرایه نیز مانند بردار و ماتریس **همگن** است؛ یعنی همه عناصر آن باید از یک نوع باشند.

### 🧪 معادل آزمایشگاهی

اگر ماتریس را یک پلیت 96 خانه‌ای تصور کنیم، آرایه شبیه چند پلیت است که روی یکدیگر قرار گرفته‌اند.

هر پلیت می‌تواند نماینده یک زمان، یک بافت یا یک شرایط آزمایشی باشد.

---

## ۱۷. ساخت یک آرایه سه‌بعدی

ابتدا چند مقدار فرضی تولید می‌کنیم:

```r
time_series_values <- c(
  120, 65, 340,
  125, 70, 355,
  150, 90, 400,
  145, 88, 390,
  180, 110, 450,
  175, 105, 440
)
```

سپس آرایه را می‌سازیم:

```r
expression_array <- array(
  time_series_values,
  dim = c(3, 2, 3)
)
```

عبارت زیر:

```r
dim = c(3, 2, 3)
```

یعنی آرایه ما دارای این ابعاد است:

```text
3 ژن × 2 بیمار × 3 زمان
```

برای نام‌گذاری ابعاد:

```r
dimnames(expression_array) <- list(
  Genes = c("TP53", "BRCA1", "EGFR"),
  Patients = c("Patient_1", "Patient_2"),
  Timepoints = c("Before", "12h", "24h")
)
```

اکنون می‌توانیم داده مربوط به زمان قبل از درمان را ببینیم:

```r
expression_array[, , "Before"]
```

یا بیان ژن `TP53` را در تمام بیماران و زمان‌ها استخراج کنیم:

```r
expression_array["TP53", , ]
```

### 🔍 انتخاب، ✏️ تغییر و 🗑️ حذف در آرایه

در یک آرایه سه‌بعدی، سه جایگاه داخل براکت داریم:

```r
array[Genes, Patients, Timepoints]
```

انتخاب یک مقدار مشخص:

```r
expression_array[
  "TP53",
  "Patient_1",
  "Before"
]
```

تغییر همان مقدار:

```r
expression_array[
  "TP53",
  "Patient_1",
  "Before"
] <- 150
```

حذف ژن اول:

```r
expression_array <- expression_array[-1, , ]
```

حذف بیمار آخر:

```r
expression_array <- expression_array[
  ,
  -dim(expression_array)[2],

]
```

حذف اولین زمان:

```r
expression_array <- expression_array[, , -1]
```

> [!NOTE]
> در آرایه، هر جایگاه داخل براکت نماینده یک بُعد است. خالی‌گذاشتن یک جایگاه یعنی تمام عناصر آن بُعد انتخاب شوند.

---

## ۱۸. آیا در RNA-Seq زیاد از آرایه استفاده می‌کنیم؟

در تحلیل‌های معمول bulk RNA-Seq، داده خام شمارش اغلب به شکل یک ماتریس ذخیره می‌شود؛ زیرا دو بُعد اصلی ما ژن و نمونه هستند.

اما آرایه‌ها زمانی مفیدند که یک بُعد اضافی داشته باشیم، مانند:

* زمان
* بافت
* نوع درمان
* تکرار فنی
* موقعیت فضایی
* کانال تصویربرداری

نکته مهم این نیست که همه داده‌ها را حتماً به آرایه تبدیل کنیم؛ بلکه باید بدانیم هرگاه داده ما واقعاً بیش از دو بُعد داشت، R چنین ظرفی را در اختیار ما قرار می‌دهد.

---

# بخش چهارم: دیتا فریم؛ دفتر ثبت مشخصات نمونه‌ها

## ۱۹. آیا ماتریس می‌تواند همه اطلاعات پروژه را نگهداری کند؟

ماتریس شمارش ما فقط عدد دارد:

```r
count_matrix
```

اما درباره هر نمونه اطلاعات دیگری نیز داریم:

* شناسه نمونه
* نوع بافت
* سن بیمار
* جنسیت
* وضعیت پاسخ به درمان
* شماره Batch
* زمان نمونه‌برداری

این اطلاعات همگی هم‌نوع نیستند.

برای مثال:

```text
Sample_ID    → متن
Age          → عدد
Is_Tumor     → منطقی
Sex          → دسته‌بندی
```

اگر این مقادیر را داخل یک ماتریس قرار دهیم، به دلیل قانون همگنی، احتمالاً همه‌چیز به متن تبدیل می‌شود.

پس به یک ساختمان داده دوبعدی نیاز داریم که برخلاف ماتریس، اجازه دهد ستون‌های مختلف نوع‌های متفاوت داشته باشند.

---

## ۲۰. دیتا فریم (`Data Frame`) چیست؟

دیتا فریم یک ساختمان داده دوبعدی و **ناهمگن** است.

دوبعدی است؛ چون سطر و ستون دارد.

ناهمگن است؛ چون هر ستون می‌تواند نوع متفاوتی داشته باشد.

در یک دیتا فریم:

* هر سطر معمولاً یک مشاهده، بیمار یا نمونه است؛
* هر ستون یک متغیر یا ویژگی را نشان می‌دهد.

### 🧪 معادل آزمایشگاهی

دیتا فریم شبیه دفتر ثبت نمونه‌های آزمایشگاه است.

هر ردیف مربوط به یک نمونه است، اما ستون‌ها اطلاعات متفاوتی را ثبت می‌کنند:

* کد نمونه
* سن بیمار
* نوع بافت
* تاریخ دریافت
* وضعیت کنترل کیفیت

همه ستون‌ها درباره یک مجموعه نمونه صحبت می‌کنند، اما محتوای آن‌ها یکسان نیست.

---

## ۲۱. ساخت جدول مشخصات نمونه‌های RNA-Seq

```r

```

* ستون `Is_Tumor` منطقی است.

این تنوع در ماتریس امکان‌پذیر نبود، اما در دیتا فریم کاملاً طبیعی است.

---

## ۲۲. دیتا فریم از درون چگونه ساخته شده است؟

در ظاهر، دیتا فریم شبیه یک جدول است؛ اما از نظر داخلی می‌توان آن را مجموعه‌ای از بردارهای هم‌اندازه در نظر گرفت.

در مثال ما:

```r

```

```r
sample_metadata$Age
```

```r
sample_metadata$Is_Tumor
```

تمام این بردارها باید طول یکسان داشته باشند؛ زیرا هر عنصر از آن‌ها متعلق به یک سطر مشخص است.

مثلاً عنصر اول همه ستون‌ها درباره نمونه `Tumor_1` صحبت می‌کند:

```text
Tumor_1 | Tumor | 54 | TRUE
```

# بخش پنجم: فاکتور؛ وقتی دسته‌ها فقط متن نیستند

## ۲۶. آیا ستون Tissue فقط یک متن معمولی است؟

در دیتا فریم ما ستون زیر وجود دارد:

```r
sample_metadata$Tissue
```

این ستون شامل دو عبارت است:

```text
Tumor
Normal
```

در نگاه اول این‌ها فقط متن هستند، اما از دید آماری یک معنای مهم دارند:

این مقادیر نشان‌دهنده دو **گروه آزمایشی** هستند.

R باید بداند که:

* `Tumor` یک جمله یا توضیح آزاد نیست؛
* `Normal` نیز یک متن تصادفی نیست؛
* این دو مقدار، سطوح یک متغیر دسته‌ای هستند.

برای نمایش داده‌های دسته‌ای، R ساختمانی به نام **فاکتور** دارد.

---

## ۲۷. فاکتور (`Factor`) چیست؟

فاکتور برای نگهداری و مدیریت داده‌های دسته‌ای یا `Categorical Data` استفاده می‌شود.

نمونه‌هایی از داده دسته‌ای:

* تومور و نرمال
* زن و مرد
* پاسخ‌دهنده و غیرپاسخ‌دهنده
* مراحل سرطان
* گروه کنترل و درمان
* نوع بافت

دسته‌های ممکن یک فاکتور، **سطوح** یا `Levels` نام دارند.

ستون بافت را به فاکتور تبدیل می‌کنیم:

```r
sample_metadata$Tissue <- factor(
  sample_metadata$Tissue
)
```

اکنون:

```r
sample_metadata$Tissue
```

خروجی علاوه بر مقادیر، سطوح را نیز نمایش می‌دهد:

```text
[1] Tumor  Tumor  Normal Normal
Levels: Normal Tumor
```

برای مشاهده سطوح:

```r
levels(sample_metadata$Tissue)
```

---

## ۲۸. چرا ترتیب Levels اهمیت دارد؟

در بسیاری از تحلیل‌های آماری، به‌ویژه تحلیل بیان تفاضلی، یکی از گروه‌ها به‌عنوان گروه مرجع یا `Reference Level` در نظر گرفته می‌شود.

فرض کنید می‌خواهیم تغییر بیان ژن‌ها را در تومور نسبت به نرمال بررسی کنیم.

از نظر مفهومی، سؤال ما این است:

```text
Tumor در مقایسه با Normal
```

پس منطقی است که `Normal` گروه مرجع باشد.

سطوح را صریح تعیین می‌کنیم:

```r
sample_metadata$Tissue <- factor(
  sample_metadata$Tissue,
  levels = c("Normal", "Tumor")
)
```

در این حالت:

* `Normal` سطح اول و گروه مرجع است؛
* `Tumor` با آن مقایسه می‌شود.

این موضوع بعدها هنگام کار با `DESeq2` اهمیت بسیار زیادی پیدا خواهد کرد؛ زیرا جهت `Fold Change` و تفسیر نتایج به تعریف گروه مرجع وابسته است.

---

## ۲۹. داده اسمی و رتبه‌ای

فاکتورها می‌توانند دو شکل اصلی داشته باشند.

### الف) داده اسمی (`Nominal`)

در داده اسمی، دسته‌ها ترتیب طبیعی ندارند.

مثال:

```r
blood_group <- factor(
  c("A", "O", "B", "AB", "A")
)
```

نمی‌توان گفت گروه خونی A از B بزرگ‌تر یا کوچک‌تر است.

### ب) داده رتبه‌ای (`Ordinal`)

در داده رتبه‌ای، سطوح دارای ترتیب‌اند.

مثلاً مراحل سرطان:

```r
cancer_stage <- factor(
  c(
    "Stage II",
    "Stage I",
    "Stage IV",
    "Stage III"
  ),
  levels = c(
    "Stage I",
    "Stage II",
    "Stage III",
    "Stage IV"
  ),
  ordered = TRUE
)
```

در اینجا ترتیب مراحل معنا دارد:

```text
Stage I < Stage II < Stage III < Stage IV
```

برای بررسی رتبه‌ای‌بودن:

```r
is.ordered(cancer_stage)
```

خروجی:

```text
[1] TRUE
```

## ۳۰. فاکتور از نظر داخلی چیست؟

فاکتور در ظاهر برچسب‌های متنی نشان می‌دهد، اما درون R معمولاً بر پایه کدهای عدد صحیح و یک ویژگی به نام `levels` ساخته می‌شود.

مثلاً:

```r
group <- factor(
  c("Control", "Treatment", "Control")
)
```

R می‌تواند در پشت صحنه آن را تقریباً به این شکل نگهداری کند:

```text
Control   → 1
Treatment → 2
Control   → 1
```

و سپس برچسب‌ها را از طریق `levels` نمایش دهد.

به همین دلیل، تبدیل مستقیم فاکتور به عدد می‌تواند خطرناک باشد.

مثلاً:

```r
numeric_factor <- factor(c("10", "20", "30"))
as.numeric(numeric_factor)
```

خروجی ممکن است این باشد:

```text
[1] 1 2 3
```

نه:

```text
10 20 30
```

زیرا R کد داخلی سطح‌ها را برگردانده است.

برای تبدیل صحیح:

```r
as.numeric(as.character(numeric_factor))
```

این یکی از خطاهای کلاسیک در تحلیل داده با R است.

### 🔍 انتخاب، ✏️ تغییر و 🗑️ حذف در فاکتور

از آنجا که فاکتور بر پایه یک بردار ساخته می‌شود، انتخاب عناصر آن شبیه بردار است:

```r
sample_metadata$Tissue[1]
```

انتخاب نمونه‌های توموری:

```r
sample_metadata$Tissue[
  sample_metadata$Tissue == "Tumor"
]
```

تغییر یک مقدار:

```r
sample_metadata$Tissue[1] <- "Normal"
```

> [!WARNING]
> مقدار جدید باید از قبل در `levels` فاکتور وجود داشته باشد.

حذف اولین عنصر:

```r
tissue_factor <- sample_metadata$Tissue[-1]
```

پس از حذف داده‌ها، ممکن است بعضی Levelها دیگر استفاده نشوند. برای حذف Levelهای بدون استفاده:

```r
tissue_factor <- droplevels(tissue_factor)
```

# بخش ششم: لیست؛ یک پرونده برای نگهداری همه‌چیز

## ۳۱. هنوز یک مشکل باقی مانده است

تا اینجا برای هر نوع اطلاعات یک ظرف مناسب پیدا کرده‌ایم:

* بیان یک ژن در چند نمونه → بردار
* بیان چند ژن در چند نمونه → ماتریس
* داده چندبعدی → آرایه
* مشخصات نمونه‌ها → دیتا فریم
* گروه‌های آزمایشی → فاکتور

اما اگر بخواهیم تمام اطلاعات پروژه RNA-Seq را در یک شیء واحد نگهداری کنیم چه؟

ما ممکن است هم‌زمان این موارد را داشته باشیم:

```text
Count Matrix       → ماتریس
Sample Metadata    → دیتا فریم
Target Genes       → بردار
Analysis Settings  → مقادیر مختلف
Project Name       → متن
Quality Status     → مقدار منطقی
```

این اشیاء هم‌اندازه و هم‌نوع نیستند.

بردار، ماتریس و آرایه نمی‌توانند همه آن‌ها را کنار هم نگه دارند؛ زیرا همگن هستند.

دیتا فریم نیز برای این کار طراحی نشده است؛ چون اجزای ما لزوماً ستون‌های هم‌اندازه نیستند.

اینجاست که انعطاف‌پذیرترین ظرف R وارد می‌شود.

---

## ۳۲. لیست (`List`) چیست؟

لیست یک ساختمان داده ناهمگن است که می‌تواند تقریباً هر نوع شیئی را در خود نگهداری کند.

اجزای یک لیست می‌توانند شامل موارد زیر باشند:

* یک عدد
* یک رشته متنی
* یک بردار
* یک ماتریس
* یک دیتا فریم
* یک تابع
* یک لیست دیگر

### 🧪 معادل آزمایشگاهی

لیست را می‌توان مانند پرونده کامل یک پروژه یا بیمار در نظر گرفت.

داخل پرونده ممکن است چیزهای متفاوتی وجود داشته باشد:

* برگه مشخصات بیمار
* تصویر پزشکی
* نتایج آزمایش خون
* گزارش پاتولوژی
* یادداشت پزشک
* نسخه دارویی

همه این موارد از یک نوع نیستند، اما همگی به یک بیمار تعلق دارند.

مثلاً یک آزمون آماری ممکن است هم‌زمان این خروجی‌ها را تولید کند:

* آماره آزمون

* فاصله اطمینان
* روش آزمون
* فرض جایگزین
* داده‌های استفاده‌شده

چون این خروجی‌ها از یک نوع نیستند، R آن‌ها را داخل یک لیست قرار می‌دهد.

مثلاً:

```r
control_expression <- c(10, 12, 9, 11, 13)
tumor_expression <- c(18, 21, 17, 20, 19)

test_result <- t.test(
  tumor_expression,

)
```

ساختار خروجی را بررسی می‌کنیم:

```r
str(test_result)
```

```r
test_result$p.value
```

```r
test_result$statistic
```

```r
test_result$conf.int
```

بنابراین وقتی در آینده خروجی توابع پیچیده‌ای مانند مدل‌های آماری یا ابزارهای Bioconductor را دیدید، از تعداد زیاد اطلاعات نترسید. احتمالاً با یک لیست یا یک شیء پیچیده مبتنی بر لیست روبه‌رو هستید.

# بخش هفتم: نقشه خانواده ساختمان داده‌ها

## ۳۷. حالا تمام ظرف‌ها را کنار یکدیگر بگذاریم

ساختمان داده‌هایی که یاد گرفتیم، تصادفی و جدا از یکدیگر نیستند. میان آن‌ها یک رابطه منطقی وجود دارد.

```text
                     ساختمان داده‌ها
                            |
            ---------------------------------
            |                               |
          همگن                            ناهمگن
   Homogeneous                      Heterogeneous
            |                               |
     ----------------               ----------------
     |       |      |               |              |
   Vector  Matrix  Array        Data Frame        List
```

### خانواده همگن

در این ساختمان‌ها همه عناصر باید از یک نوع باشند:

* بردار
* ماتریس
* آرایه

تفاوت آن‌ها بیشتر در تعداد ابعاد است:

```text
Vector → یک‌بعدی
Matrix → دوبعدی
Array  → چندبعدی
```

### خانواده ناهمگن

این ساختمان‌ها می‌توانند انواع مختلف داده را کنار هم نگه دارند:

* دیتا فریم
* لیست

اما کاربرد آن‌ها متفاوت است:

* دیتا فریم برای داده‌های جدولی و ستون‌های هم‌اندازه مناسب است.
* لیست برای مجموعه‌ای از اشیاء متفاوت با اندازه‌ها و ساختارهای مختلف مناسب است.

### جایگاه فاکتور

فاکتور برای نمایش متغیرهای دسته‌ای استفاده می‌شود و از نظر داخلی بر پایه یک بردار عدد صحیح همراه با سطوح ساخته شده است.

فاکتور معمولاً به‌عنوان یکی از ستون‌های یک دیتا فریم دیده می‌شود:

```r
sample_metadata$Tissue
```

# 🧭 الگوی مشترک انتخاب، تغییر و حذف

با وجود تفاوت ساختمان داده‌ها، منطق کلی کار با آن‌ها مشابه است:

| عملیات | الگوی کلی |
|---|---|
| 🔍 انتخاب | `x[index]` |
| ✏️ تغییر | `x[index] <- new_value` |
| 🗑️ حذف | `x <- x[-index]` |
| 🧹 حذف براساس شرط | `x <- x[condition]` |

> [!IMPORTANT]
> در R حذف‌کردن معمولاً به این معنی است که نسخه‌ای تازه از شیء ساخته می‌شود که عنصر نامطلوب در آن انتخاب نشده است.

# جمع‌بندی جلسه

در این جلسه یاد گرفتیم که R داده‌ها را به شکل تصادفی در حافظه قرار نمی‌دهد. ما باید براساس ماهیت داده، ظرف مناسبی را انتخاب کنیم.

* وقتی چند مقدار هم‌نوع را پشت سر هم داریم، از **بردار** استفاده می‌کنیم.
* وقتی داده هم‌نوع ما سطر و ستون دارد، از **ماتریس** استفاده می‌کنیم.
* وقتی بیش از دو بُعد داریم، از **آرایه** کمک می‌گیریم.
* وقتی یک جدول با ستون‌های متفاوت داریم، به **دیتا فریم** نیاز داریم.
* وقتی مقادیر نشان‌دهنده گروه‌های آماری هستند، آن‌ها را به **فاکتور** تبدیل می‌کنیم.
* وقتی می‌خواهیم چند شیء کاملاً متفاوت را در یک پرونده قرار دهیم، از **لیست** استفاده می‌کنیم.

اما مهم‌ترین پیام این جلسه حفظ‌کردن تعریف‌ها نیست.

مهم‌ترین مهارتی که باید به دست آورید این است که وقتی با یک داده زیستی جدید روبه‌رو می‌شوید، از خودتان بپرسید:

1. داده من چند بُعد دارد؟
2. آیا همه مقادیر از یک نوع هستند؟
3. آیا داده من جدولی است؟
4. آیا مقادیر من نماینده گروه‌های آماری هستند؟
5. آیا می‌خواهم چند شیء متفاوت را کنار هم نگه دارم؟

پاسخ همین سؤال‌ها ساختمان داده مناسب را مشخص می‌کند.
